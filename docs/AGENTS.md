# AI Macro agent instructions

The runtime and archive architecture in `docs/RUNTIME_DATA_CONTRACT.md` is a
protected project decision.

- Public Streamlit is a strict retained-state reader. It may not call Current Context discovery, OpenAI, YFinance, EDGAR, FRED, NY Fed, or domain-data providers, and it may not write retained research state. Current Context reaches Reader mode only through the retained publication path.
- Only the desktop developer instance may contact providers or write retained
  files, and only after an explicit named refresh action.
- YFinance owns dated raw market, benchmark, sector, and macro snapshots.
- Other provider refreshes must not re-date market-derived history.
- A manual provider refresh is a real refresh transaction, not a freshness check. It must authorize that named provider for the same Streamlit execution, attempt live retrieval even when the market is closed or a retained snapshot already exists, and persist the resolved complete snapshot on success.
- Refresh intent and live authorization are separate invariants. `force_refresh=True` (or any domain-specific force flag) may request work but must never grant provider access by itself; every network-owning loader must require the matching `LoadPolicy` authorization in the same execution before it contacts a provider.
- For YFinance, "complete" means every configured ticker returned a live row. Missing optional fields may be filled from the prior retained snapshot and reported as retained field fills; they do not block the archive write. A missing ticker row or retained ticker-row fallback does block the write.
- The fixed QQQ reference is part of the same YFinance analytical transaction. Build it from the resolved YFinance market universe and require the same `Market Data Date` before YFinance, benchmark, sector, or macro histories advance. The retained universe contains GOOG but not GOOGL, so the documented fixed reference maps the GOOGL weight to the retained GOOG Class C row for reproducibility.
- Archive `Date` means the date the retained snapshot was saved. Provider observation dates remain separate fields (for example YFinance `Market Data Date`). The Developer load report must not use an observation date as the "Latest complete archive" date.
- The approved unattended publication path is the single GitHub Actions automation worker. Viewer-triggered refreshes, additional background writers, automatic retry loops, or alternate publication paths remain prohibited unless the user explicitly approves them. The worker is bounded by deterministic validation, hard paid-call ceilings, and Git commit as the publication transaction.
- The application runtime requires Python 3.11 or newer. Developer mode is an owner-controlled environment mode for local/desktop execution; hosted Reader deployments must leave `AI_MACRO_MODE` unset or explicitly `public`.
- Architectural replacements renovate the active path; they do not leave superseded engines or provider routes walled off behind compatibility flags. Deletions must be surgical: trace callers and data responsibilities first, replace coverage before removal, test the focused dependency immediately, and do not perform speculative adjacent cleanup.
- Do not expand the test system beyond bounded contracts tied to a demonstrated
  material failure. Modify an existing contract check when possible.
- Preserve the user's metric names and analytical intent unless the user
  explicitly approves a redesign.
- Debt Financing Pulse may use only issuer-matched, definition-matched SEC debt
  observations with period-matched TTM CapEx. Never substitute a vendor total
  debt value or accept one leg of a multi-part debt definition. An explicit EDGAR refresh must rebuild the retained 10-company SEC Finance fundamentals cohort and preserve both a comparable prior-year and current observation for the definition-matched debt cohort. Prefer one common complete standard XBRL debt group across both dates. When Companyfacts cannot express the issuer's canonical definition completely, a filing-reviewed retained pair may be used only if it preserves that exact definition and aligns to the current CapEx period. Do not advance only the current debt period and thereby collapse the matched cohort. The Developer load report must distinguish automatic Companyfacts updates, filing-reviewed fallbacks, and unresolved issuers.
- Funding-card histories use a trailing five-calendar-year display. Forward
  Commitment Load must use only uncommenced leases plus purchase or contractual
  commitments, as available by each observation date, matched to four-quarter
  SEC CapEx. Do not splice mixed commitment categories into the history.
- `data/capital_commitment_components.csv` is the source of truth for the current Forward Commitment numerator. Each component keeps its own value, as-of date, filing date, source, scope, and carry-forward status; `data/capital_commitments.csv` is a generated compatibility view. Broad company-wide disclosures must remain labeled as broad rather than being attributed wholly to AI. Later filings may carry a component forward only when that status is explicit; do not silently mix filing vintages.
- AEI uses the same two factors and weights for all sectors. Do not introduce a
  sector-specific factor, insurance exception, or security-specific scoring
  rule. Valuation is a separate diagnostic, not an AEI or Trading Pressure
  input. Shiller CAPE belongs only in Market's current-conditions valuation context, with its observation date and historical reference visible; it must not feed AEI or Trading Pressure.
- A market-basket membership change requires backfilling every raw market
  factor for the complete universe and rebuilding sector and macro history on
  the retained raw market dates. Never splice a new universe onto old scores.
- Ambiguous data-center identities belong in
  `data/facility_identity_decisions.csv` with record-level evidence. Do not
  broaden fuzzy-match thresholds to resolve one named project, and do not
  combine published capacity values within a campus; the campus uses the
  strongest applicable observation rather than an additive total.
- `data/release_manifest.json` is the publication boundary for the critical
  retained archives and analytical contracts. Run
  `python helpers/build_release_manifest.py` only after the intended release is
  complete, then run `python helpers/integrity_gate.py`. Do not hand-edit the
  manifest or silently publish a stale fingerprint.
- Read confidence remains internal evidence-completeness metadata; do not put a
  generic high/moderate/limited confidence label back on the public narrative.
  Domain language must name the observed population or proxy when a result is
  not an economy-wide or causal measure.
- Streamlit is the sole owner of Plotly chart width through
  `st.plotly_chart(..., width="stretch")`. Do not set or clear `layout.width`,
  force `layout.autosize`, or apply sizing CSS to chart-bearing
  `stElementContainer` paths, `stFullScreenFrame`, `stPlotlyChart`,
  `.js-plotly-plot`, `.plot-container`, or `.svg-container`. Narrow sizing on
  named pure-markdown layout wrappers is permitted when it cannot select a
  Plotly-bearing container. Competing chart geometry rules caused the verified
  700 px fallback regression in wide panels.
- Domain tabs are tracked with `on_change="rerun"`, and only the tab whose
  `.open` state is true may render. Do not eagerly render hidden domain tabs:
  hidden Plotly surfaces initialize without a measurable width and can retain
  the fallback when activated, particularly in Firefox.

## Editorial language contract

Public copy is governed by `docs/EDITORIAL_STYLE.md`.

- Use plain, specific titles, subtitles, captions, and helper text. Do not add research-product jargon to make an ordinary comparison sound more sophisticated.
- The platform identity copy is protected. Do not rewrite the masthead subheader or `METRIC_DEFINITIONS["Purpose Statement"]` during editorial, presentation, Read, or maintenance work unless the user explicitly asks to change that exact copy. Existing approved wording must be preserved verbatim.
- v7 commentary is generated from deterministic evidence packets, not from raw provider payloads or a legacy prose engine. The model may interpret, synthesize, and prioritize supplied facts; it may not establish canonical facts, calculations, persistence, or publication permission.
- Every generated sentence must cite one or more supplied evidence `fact_id` values and pass the deterministic publication validator before it can be promoted or rendered. Every completed paid OpenAI response is first persisted under local `openai_artifacts/attempts/` for audit/recovery, including rejected responses. Unsupported numeric claims, unknown/out-of-scope fact IDs, schema failures, or snapshot mismatch fail closed for publication.
- If validated commentary is missing or stale, the Reader uses the single compact unavailable state; do not preserve or reintroduce a deterministic **analytical Read** fallback. Current Context is a separate exception: once a source-grounded development clears its evidence gates, it may use bounded deterministic mechanism synthesis to explain the domain consequence. Ordinary source/update packages must exclude `openai_artifacts/` so paid local generation history survives code replacement.
- Domain commentary is generated first; Macro synthesis may use only the validated domain conclusions plus the same bounded evidence packets and must select 4–6 domains spanning at least three lifecycle stages. Do not turn the OpenAI layer into an agent or give it provider/data-refresh ownership.
- Preserve formal metric definitions and source-field semantics. If an internal metric name is jargon-heavy, prefer a plain display label rather than changing the calculation or stored field name.
- Keep statistics subordinate to interpretation. Do not turn the Read into a list of current values already visible elsewhere on the page. Domain Reads use a headline plus 3–5 grounded analytical sentences. AI Macro uses exactly four grounded sentences rendered as two short paragraphs. Its substance should satisfy an expert while its language remains readable to a smart non-specialist: simplify wording and sentence structure, never insert glossary-style definitions into the Read. The model-facing field is `analysis`, not `summary`. Use numbers selectively and make the relationship among facts do the explanatory work.
- Reader commentary has no Watch/watchpoint/catalyst section. Do not reintroduce trading-terminal language, a separate forward-monitoring line, or a forecast placeholder into the Read schema or renderer.
- Recent Developments assumes no prior article context or regional political knowledge. The first sentence must identify its actor directly: no mystery nouns such as “the chipmaker,” dangling pronouns, or unexplained specialized acronyms. Resolve identity only from the source body/headline; if that cannot be done safely, omit the item. Public officials still require jurisdiction, title, and full name on first reference.
- Every Current Context domain uses one canonical seven-calendar-day qualification grammar: eligible evidence source, freshness, domain relevance, a domain-specific topic anchor, and substantive domain-specific materiality. Rank score orders already-qualified items; it is never a pass/fail acceptance threshold. Retain at most two qualified developments per domain and allow zero when nothing clears the bar. Market and Finance are high-cadence anchor domains: once a source-grounded, materially qualified event survives their evidence gates, absence of a bespoke deterministic phrase must never be the reason the domain renders empty.
- Materiality precedes extraction. Current Context must first establish a clear, current, domain-material development from the evidence source's title/lead body before it extracts a factual anchor for Reader prose. Do not search a weak, commentary-first, or merely AI-adjacent article for an isolated fact that can be used to rationalize inclusion. Historical facts may support a current development but may not become the Recent Development unless they are explicitly tied to a current-period observation/action.
- AI relevance and domain significance are separate gates. In Market, company-specific AI news must also have genuine market significance: broad market/sector read-through, a systemically important AI/technology issuer, an unusually large public-market repricing, or a major transaction. Valid company evidence that lacks Market-level significance should yield no Market item rather than consume a scarce slot.
- Discovery metadata is nomination only. A headline, RSS title, snippet, feed description, or discovered publisher URL nominates an event; none is itself the factual basis of Reader-facing Recent Developments prose. The canonical Current Context path must try the nominated evidence route first and, when that route is inaccessible or insufficient for a non-disqualifying reason, research the same event through other eligible primary records or approved independent reporting. Every evidentiary endpoint must pass the same substantive source-body grounding contract before Reader prose is allowed. If no eligible evidence path establishes the event, publish zero items rather than substitute headline-derived prose.
- Google News RSS wrappers are discovery transport, never evidence URLs. Modern opaque Google News article IDs must resolve through the canonical Google decode handshake before a discovered publisher page is used. A host mismatch rejects that evidence route, not necessarily the underlying event. `current_context_discovery` is the single network owner and may perform a bounded event-level evidence search for another eligible source covering the same event; alternate routing must preserve the original event identity, satisfy event-similarity/recency checks, avoid merely retrying the same publisher, and then pass the exact same source-body grounding gates. Source grounding must continue down the ranked qualified queue until it has enough grounded candidates for final 0–2 selection or the bounded request/search budgets are exhausted.
- Publisher publication date controls Current Context freshness when it is available. A recently recrawled/reindexed old page is not a new development; `dateModified` may be used only when the page exposes no publication date. Full fetched article/release bodies are transient refresh inputs and must never be persisted. Retain only the resolved evidence URL, compact derived prose, source dates, extraction method/size, and an evidence hash sufficient for audit.
- High-bar exclusions are semantic, not merely score-based: routine policymaker outlook commentary, previews, nonbinding roadmaps/explainers, pundit interviews, and generic international infrastructure projects do not qualify merely because they contain domain vocabulary. Workforce, Adoption, and Economic Outcomes automated items require a quantified observed result. Connectivity must establish a compute-market or strategic U.S. route connection in the grounded fact itself.
- Every domain uses several narrow discovery queries rather than a monolithic search. GDELT is not part of AI Macro Current Context and should not be reintroduced as a dormant fallback. Direct primary feeds and approved business reporting are eligible evidence paths. Techmeme, Abnormal Returns, Data Center Richness, and any future Tier-2 curator are discovery-only: harvest eligible outbound evidence and never cite the intermediary merely because it surfaced the lead.
- Current Context source policy is a business-research policy, not a generic prestige-media policy. Automated eligible general sources include WSJ, Reuters, Bloomberg, Financial Times, Barron's, Investor's Business Daily, Morningstar, and CNBC. Business Wire may establish an issuer statement but must remain labeled as a company statement rather than independent reporting. Associated Press is excluded from the unattended Current Context evidence path.
- Evidence navigation should make the shortest useful path from the published interpretation to the facts it cites, the retained source foundation, and the relevant scope or boundary. The default Reader surface should present that trace cleanly; formulas, raw registers, and full observation tables belong in an explicitly technical layer rather than competing with the main evidence path. Prefer navigation and source tracing over decorative Evidence charts.
- Evidence methodology is protected: secondary aggregators are discovery-only until traced to eligible underlying evidence; corroboration requires an independent evidentiary chain rather than repeated publication of the same upstream source; and social media is excluded from discovery, corroboration, evidence, and citation. Preserve the actor, authority, and procedural status of political or regulatory actions exactly as established by the primary record.
- The reader-facing `Evidence standards` statement is protected methodology copy. Do not rewrite or shorten it during general editorial, presentation, or maintenance passes unless the user explicitly asks to change that statement.
- `README.md` is the short repository-facing overview of the product. Keep it brief and durable. Do not turn it into release notes, a changelog, a contributor guide, or a local installation guide. Describe the actual access model: Reader mode for users and owner-only Developer mode.
- Every packaged user-facing upgrade must increment `APP_VERSION` before delivery. Never ship two distinct upgrade archives with the same application version. Use a patch bump for maintenance/editorial changes and a minor or major bump only when the scope warrants it. Keep app versioning separate from the session-state schema unless the session-state contract itself changes.
- Do not overwrite a newer retained archive from the owner's working copy with an older archive carried forward from a prior package. If the current retained-data state is not available in the conversation, use a code-only overlay for maintenance changes or clearly identify the stale archive boundary before packaging a full project copy.
- Generic Reader labels must resolve to the canonical domain title plus `Read` (for example `Market Read`, `Data Centers Read`, and `AI Macro Read`). Keep this in the shared Read renderer rather than local tab overrides.
- Developer retained startup and every Public Reader startup must make zero Current Context provider calls. Public Reader mode loads only retained Current Context. The desktop developer refresh and the approved automation worker are the only discovery writers. Commentary remains independently bound to the deterministic evidence snapshot; the Reader Snapshot records both analytical and Current Context identities. When a retained developer manifest predates the installed discovery engine, Developer Tools must surface the engine/snapshot mismatch rather than silently implying that the new engine has been exercised.
- Auditable Current Context discovery must preserve transport failures. A provider error must never be represented as a successful zero-result query.
- Current Context persistence and retained reload are one contract: automated evidence states (`reported`, `primary`, `company_statement`, `independently_retrieved`) must survive select → persist → reload → Read attachment. Do not silently reduce the retained loader to legacy `confirmed`/`corroborated` rows.
- A source-grounded Current Context row does not become invalid merely because the discovery/grounding engine version advances. For automated rows, `grounded` status + a non-empty evidence hash + substantive source-text provenance establish the durable evidence contract; engine version is provenance. Within the domain freshness window, use the most recently retrieved vetted row for an `event_id` unless a newer row explicitly supersedes/revokes it. `weekly_context_events.csv` is a current-state registry and rediscovery is an upsert; the candidate audit owns historical trace.
- Every shared domain Read uses thin internal separators between the Read narrative, Recent developments (when present), and References. When Recent developments is absent, References still receives the separator directly below the Read; no orphaned divider or empty vertical gap.
- Recent Developments prose must state the development directly and then summarize or interpret the economically relevant information established by the source. Do not lead with publisher names (for example `Reuters reports:` or `Morningstar reports:`) and do not publish generic suffixes such as `The development may change...`; source identity belongs in the numbered citation and Evidence lineage. Selection rationale belongs only in Developer audit fields. Reader prose must never explain that an item qualifies, cleared a threshold, is a "direct test," or was selected because of the type of evidence.
- Preview pieces, week-ahead calendars, listicles, and generic adjacent-industry items are not developments. Market/Finance qualification must remain materially tied to AI/technology/infrastructure or a genuinely system-wide financing condition; topical vocabulary alone is insufficient.
- Evidence lineage must distinguish retained analytical evidence from Current Context, preserve discovery provenance internally, and show the actual evidence source rather than promoting a Tier-2 curator to Reader-facing authority. Search/filter controls may narrow this lineage but must not alter the underlying evidence contract.
